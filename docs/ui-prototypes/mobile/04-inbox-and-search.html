Decisions these screens make

  • Inbox is the reason to open the phone. Its tabs are Needs you · Done · Failed; Needs you groups by kind (permissions, questions, plans) so the eye finds the quick ones first. The count on the pill badge is the Needs-you count.
  • Answer from the row. A permission's provider-ordered choices and a question's options render inline under the row (CAL-303, through interaction.respond); a plan opens the session, since reading it needs the page. Answering on the phone settles it on web at once, because the server owns the interaction.
  • Done rows are unseen → seen, swipe to mark, or the ✓✓ button for all; the row dims when seen on another device, which is the same acknowledge state web keeps.
  • Search is a layer, not a tab. Field, filters (All / Active / Needs you / Project / Drafts), results as the standard rows with the match bolded, grouped Sessions then Drafts. Title + project only, because that is what the server indexes today.
