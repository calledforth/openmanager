Decisions these screens make

  • Settings is the third tab, and environments are the first thing in it. Cards, not rows, because each one carries a live status, the route it's on and a latency, and because switching environment is the main thing you do here.
  • Environment detail shows routes as facts: which one is in use, which answer, which don't. The phone never picks a route the server hasn't offered; fallback order is the server's list. The only client-side action is Forget, which touches phone storage only.
  • Pairing has two doors and nothing else: scan a QR, or paste a link. Both land in the same connecting → paired sheet, which names the machine, the route it landed on and what it found. No account screen, no password, no "advanced".
  • Drafts are a tab on Sessions, scoped to the current environment, with other environments' drafts one tap away. Rows show the first line, project, picks, and the Not synced state from the web draft work (CAL-85). Swipe to delete; tap to load into the expanded composer.
  • Project picker is the same bottom sheet as the model picker (file 02): search on top, recents first, then one group per environment. The folder browser (CAL-200 on web) is a second page inside the same sheet, not a new screen.

Theme sharing, concretely

Every colour on these frames comes from the same token names web uses (--bg, --fg, --muted, --faint, --hover, --active, status colours, the float shadow recipe). The RN build reads a generated token map per theme family × mode; the swatches on the Settings screen are the families from theme-families.ts. Glass is the one thing that isn't a token: it's a per-platform recipe (BlurView on iOS/Android) fed by the same --glass colours.
